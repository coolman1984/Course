# تاريخ الأداة: أسبوعين في جدول واحد (الوحدة ٤، المثال الأول)

ده نفس داشبورد الوحدة ٣، بس في أبسط صورة: أسبوعين بدل ١٣، وبلد واحد بدل الموديل والبلد. مهندس التخطيط بناه خطوة خطوة تحت قواعد قسم الأمن، وكتب السجل ده بعد كل خطوة.

| الخطوة | السكريبت | اللي اتعمل | المراجعة اللي عدّت |
|---|---|---|---|
| ١ | step1_stack.ps1 | إكسل بـ COM فتح الأسبوعين للقراءة بس، وحطهم تحت بعض في Two_Weeks.xlsx | ‏١٨ + ١٨ = ٣٦ صف، و‎٨٤٥ + ٩٢٠ = ١٬٧٦٥ جهاز |
| ٢ | step2_lookup.ps1 | شيت Countries اتنسخ، وعمود CountryName اتضاف بمعادلة VLOOKUP | ولا ‎#N/A، وعدد الصفوف لسه ٣٦ |
| ٣ | step3_report.ps1 | شيت Report بمعادلات SUMIF، وملف Two_Weeks.csv كتبه PowerShell | التقرير = البيانات = ١٬٧٦٥، والـ CSV فيه ٣٦ صف |
| ٤ | (مراجعة) | الكود اتراجع بقايمة المراجعة في جلسة جديدة | اتكشفت COUNTIF مكان SUMIF واتصلّحت: الكويت ٣٨٥ مش ٨ |
| ٥ | load_sqlite.py | Python النقي حط الجدول في Factory.db وجاوب ٣ أسئلة بـ SQL | ‏COUNT = ٣٦ وSUM = ١٬٧٦٥ من القاعدة نفسها |
| ٦ | Run_Tool.bat | الخطوات كلها بضغطة واحدة، وبتقف عند أول خطوة تفشل | ALL STEPS PASSED |

## ليه PowerShell للأوفيس وPython للباقي؟
قسم الأمن قال كلمتين: الباكدجات ممنوعة، وملفات الأوفيس عليها DRM. فكل حاجة بتفتح إكسل بقت PowerShell بطريقة COM، لأن إكسل نفسه هو اللي بيفتح الملف المتشفّر. والحساب وقاعدة البيانات بقوا Python بالمكتبة القياسية بس، وsqlite3 جاية جوّه Python من غير تثبيت.

## لو هتكمّل عليها
خطوة واحدة في المرة: سكريبت جديد بملف تشغيل لوحده، وسطر جديد في الجدول ده.
